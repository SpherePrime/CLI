# Native installer and updater audit

The default desktop development and packaging commands use Tauri. The Windows bundle is NSIS, installs for the current user and embeds the WebView2 bootstrapper. The native preview identifier and data directory remain separate from Electron because Linux/macOS credential migration is incomplete.

`npm run dist:win` builds a local Windows installer without publishing a release. `npm run dist:linux` selects AppImage, Debian and RPM bundles. Linux packaging and upgrade behavior require a real Linux desktop validation; Windows execution does not establish Linux installation parity.

Local builds have no updater public key or feed and return `unavailable`. An unverified public key was removed. No signing keys are generated. Signed builds require `PRIME_UPDATER_PUBLIC_KEY`, `PRIME_UPDATER_ENDPOINT` (HTTPS) and `TAURI_SIGNING_PRIVATE_KEY`; the optional Tauri password is passed through the environment. Missing parts fail the build rather than silently publish an unsigned feed. The private key may be a Tauri-supported key path or secret value and is never copied into generated configuration.

The tag release workflow builds native Windows x64 and Linux x64 installers, requires the existing repository signing secret and public-key variable, and publishes `latest.json` only after both signed artifacts exist. No release or tag is created by local packaging. Signature generation does not establish the publisher identity of Windows Authenticode: a code signing certificate is a separate requirement.

The updater preserves the renderer `state` contract and the information snapshot. Checking downloads and verifies an available package but never installs it. Installation requires a downloaded package, no dirty editor, active chat, terminal, team or automation. Remote projects must be closed before installation. Services shut down before replacing files; a successful installation restarts the native application. Failed replacement after shutdown requires restarting the application.

Remaining gates: real key/feed verification, signed Windows upgrade with preserved data, signed Linux AppImage upgrade/restart, Linux package-manager upgrade, legacy credential migration on Linux/macOS, ARM64 native runners, and production identifier cutover. Retained Electron dependencies and legacy scripts are archival compatibility paths; they are not bundled by Tauri.

Validation: all four packaging scripts passed JavaScript syntax checks. Isolated mocked executions passed unsigned Windows NSIS configuration, signed configuration without private key material in the generated file, incomplete signing configuration rejection, and non-HTTPS endpoint rejection. Mocked staging and publishing verified platform mapping, signature inclusion and feed merging without running GitHub commands. The release workflow parsed successfully with the local YAML parser. Native compilation, executable UI behavior and Windows installer execution are recorded with the final validation run; signed upgrade and Linux desktop installation were not executed during this audit.

WSL Ubuntu validation: `CARGO_TARGET_DIR=/tmp/prime-linux-updater-check cargo check --manifest-path desktop/src-tauri/Cargo.toml --lib` passed with exit code 0 in 1m48s with seven compiler warnings and no errors. Retained ignored log: `desktop/.workbench-linux-updater-check.log`. This compiled the updater integration for Linux without building a Linux installer. `Prime.bat setup` now invokes the native NSIS wrapper and reports its actual bundle path. Native development prepares the Go library once before starting the Vite server; renderer hot reload does not rebuild it.

The release batch verifier now accepts either the complete legacy Windows installer/feed set or the native signed Windows NSIS + signed Linux AppImage + Debian + RPM + latest.json set. Four fixture checks passed: complete native, wrong native version rejected, absent native signatures rejected, complete legacy accepted. No release was invoked.
