# Designing and checking frontend UI

Build responsive interfaces and exercise actual behavior.
Inspect existing components and design skills. Use semantic controls, accessible labels, visible focus and readable contrast. Preserve theme tokens across light/dark and printing; use a viewport, phone gutters and no accidental overflow. Implement fitting loading, empty, error and success states. Start the dev server and test primary flows and edge cases in a browser when tools support it. When browser_run is available (Prime Desktop), write the whole browser check as one scenario (widths, clicks, typing, asserts, screenshots), run it in one call, fix, and rerun the same scenario instead of driving the page step by step. Use the page, do not only look at it: click, type, submit, select, hover and Tab through the changed controls and assert the result of each action. When a desktop app's interface is a web frontend (Tauri, Electron, Vite renderer), start its dev server with the backend in the background and check it in the browser instead of launching the native app. Screenshots go from overview to close-ups: a full page reaches the model downscaled, so judge composition from it and details from component close-ups with padding, zoom 2 for small text, icons and borders, clip regions where blocks meet, and tiles for long pages. Check console failures and regressions. If browser access is unavailable, state which UI checks remain unverified; type checking is not visual evidence.
